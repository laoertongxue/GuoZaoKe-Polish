# 数据与权限说明

**简体中文** · [English](privacy.en.md)

适用产品：GuoZaoKe Polish。更新日期：2026 年 9 月 17 日。讨论分析与 B 站上传条款适用于 0.4.2 及包含相应试用功能的构建。

## 处理的数据与用途

扩展为增强过早客的浏览、阅读与编辑体验，会在浏览器中处理页面中的用户名、头像、主题与回复内容、编辑器草稿，以及用户保存的主题地址、阅读状态和自定义标签。没有作者运营的数据收集服务器，不代表扩展不处理用户数据。

页面内容用于主题预览、回复排版、用户卡片和分享图；用户名与标签用于用户标记；主题地址与阅读状态用于稍后阅读。扩展不读取 Chrome 的全局浏览历史。用户选择的本地图片只用于预览、插入与明确发起的上传。

## 数据流

- 过早客内容、用户信息、最新/最热列表及通知通过用户已有站点登录态读取；通知访问遵循原站行为。扩展不采集原站密码、Cookie 内容或原站访问令牌。用户主动填写的第三方 API Key 见下文。
- 设置和用户标签存储在 Chrome `storage.sync`；是否跨设备同步由 Chrome 同步状态决定。
- 稍后阅读条目、默认图床选择与 Imgur Client ID 存储在 `storage.local`。稍后阅读保存主题元数据，不保存整页正文。
- JSON 备份包含设置、标签和稍后阅读，不包含登录态或 Imgur Client ID。
- 分享图片在本机 Canvas 生成，不向外部分享服务发送主题内容。分享页的头像及正文图片经后台读取，不带 Cookie、不跟随重定向；预览与导出均使用读取后的内联数据。二维码在本机生成。
- 图片表情使用公开图片链接；打开表情选择器或预览时，浏览器会连接对应图片来源（如 i.imgur.com），不发送页面 Referrer。表情代码在用户提交时转换为图片链接；扩展不会自动发帖。
- 只有用户在图片对话框点击上传时，才把选中的图片发送到所选的 B 站或 Imgur，返回公共图片 URL。上传失败不会自动转交另一个图床。
- B 站上传需单独授权 `cookies` 和 `https://api.bilibili.com/*`。后台仅在主动上传时读取该域对应的 `bili_jct` 防伪 Cookie，并将其作为表单字段发送到固定的 B 站图片上传接口；浏览器随请求携带原有 B 站登录 Cookie。扩展不读取 SESSDATA 内容、不复制或持久化登录 Cookie，不同步、导出或记录防伪标记，不向页面脚本或作者传递凭证；上传不包含发布动态操作。隐身窗口上传被拒绝，避免使用错误的账号会话。
- 没有分析统计 SDK、广告 SDK 或自建遥测服务器。
- “隐藏站点广告”仅在过早客页面通过本地样式和 DOM 调整隐藏侧栏推广、已识别的 Google 广告及浮动控件，并恢复广告占位前的页面边距，不新增权限、不发送数据，也不阻止原站广告脚本或网络请求。该设置默认开启，可在控制选项关闭。

## 权限

| 权限 | 用途 |
| --- | --- |
| `storage` | 设置、标签、阅读列表、本机图床配置、分析历史与单独的会话凭据 |
| `contextMenus` | 站内选中文本解码、保存主题及设置入口 |
| `sidePanel` | 在用户打开的 Chrome 扩展侧栏中显示本帖分析工作区；此权限本身不授予额外网站访问权限 |
| `https://www.guozaoke.com/*`、`https://guozaoke.com/*` | 在目标站增强页面，并读取站点内容 |
| 可选 `cookies` 与 `https://api.bilibili.com/*` | 仅在用户启用 B 站上传后，用于读取上传所需的 B 站防伪 Cookie 与发送选中的图片；可在图床配置中撤销 |
| 可选 `https://api.imgur.com/*` | 用户配置并授权后的图片上传 |
| 可选 `https://*/*`、`http://*/*` 的声明范围 | 为图床、公开图片、用户选择的模型服务、检索服务及资料来源预留可选权限；不会一次请求通配范围。界面列出来源并由用户点击授权精确 origin；讨论分析外部请求仅允许 HTTPS |

Chrome 的 `cookies` 权限与已授予的主机权限共同生效，并不是针对单个 Cookie 的权限隔离。本扩展的实现只读取上述 B 站防伪标记；不遍历其他网站 Cookie。

图片读取器拒绝本机、已知内网 IP、凭证 URL、特殊协议与异常端口；该 URL 检查不是 DNS 解析审计。SVG 只作为 `img` 的内联图像源，不作为活动 HTML/SVG 文档插入；脚本和外部子资源遵循浏览器的 [SVG 图像模式限制](https://www.w3.org/TR/SVG2/conform.html#processing-modes)。图片来源授权可在 Chrome 的扩展管理页撤销。

## 可选的讨论分析

此功能不会自动分析访问过的帖子。用户主动打开本帖分析侧栏后，如本机没有该帖报告且模型 Key 可用，会采集当前帖子供用户检查；也可以主动点击采集。采集本身不调用模型。用户确认发送范围和预算并开始分析后，扩展才将该帖文字、原文链接、提取的主张、核查问题和选定资料正文发送到用户配置的模型 API。正文中的用户名与提及可能仍被服务商处理；界面代号不等于完全匿名。不会发送原站 Cookie、登录凭据、编辑器草稿或全局浏览历史。

用户可另外配置 Tavily 检索。启用时，核查问题及相应检索词发送至 `api.tavily.com`；搜索摘要只是线索。公开网页与文字 PDF 经用户授权的具体域名读取，不带 Cookie 和 Referrer、不跟随重定向。用户选择的本地资料先在扩展中解析，纳入分析后，其提取文本也属于模型发送范围。PDF 解析器随扩展打包，不加载远程代码。

模型 Key 与检索 Key 按用途和目的域分别放在仅限受信扩展上下文的 `storage.session`，不会返回页面内容脚本，不进入 `storage.local`、`storage.sync`、日志、分析包或常规备份。模型 Key 作为认证信息发送给用户选择的模型服务；检索 Key 发送给 Tavily。浏览器重启或扩展重载后需重新填写。保护边界不包括已被控制的设备、浏览器、扩展开发工具或服务商自身；不能保证对这些主体隐藏用户自己的凭据。

非凭据模型配置、采集原文、来源正文、分析结果、运行检查点、调用用量和校准回执保存在本机 `storage.local`。分析导出与常规设置备份分开，包含原文和来源文本；分享前应检查其内容。导出不含 Key。取消会停止安排后续请求，已经送达第三方的请求可能继续处理或计费。

内置校准使用合成样例，主动执行后才发送至所选模型服务；复跑使用用户选定的本机分析材料。扩展不将这些数据发送给作者，也不提供跨帖个人评分或人格画像。模型与检索服务会依据自身政策处理接收到的数据，用户应自行选择适合的服务。

## 清理

设置页可以管理标签、导出备份、清除图床配置。恢复默认只重置设置，不删除阅读列表或标签。卸载扩展由 Chrome 清理扩展本地数据；已经上传到 B 站或 Imgur 的文件不会因卸载扩展而删除。

分析设置可清除本次会话的全部 Key、删除模型配置；分析历史可逐条删除报告及其运行检查点。校准记录目前随扩展保存在本机，卸载时清理。恢复普通界面默认设置不清除这些分析记录。卸载或删除本机记录不会删除已经交给模型、检索或图片服务的数据。

删除讨论分析时会清除该记录的内容、任务与原件预算，保留仅含记录 ID 的本地删除标记，防止仍在运行的其他窗口把已删除内容写回。该标记不包含正文或 Key，卸载扩展时一并清除。

## 有限使用

GuoZaoKe Polish 对用户数据的使用与传输遵守 [Chrome 应用商店用户数据政策](https://developer.chrome.com/docs/webstore/program-policies/user-data)，包括有限使用要求。数据仅用于提供本说明中列出的用户可见功能，不出售给第三方，不用于广告定向，不用于信用评估或借贷决策，也不用于与扩展功能无关的目的。作者不通过扩展接收或人工查看用户的浏览内容、标签、草稿或备份。

必要的数据传输包括访问过早客、Chrome 设置同步、加载第三方公开图片、用户明确发起的 B 站或 Imgur 上传，以及主动启动讨论分析时的模型、检索和资料读取请求。相应服务会按其自身规则处理请求；上传到 B 站或 Imgur 的图片可通过公开链接访问。用户主动向 GitHub 反馈渠道提交的内容会按该渠道的可见性展示，请勿在公开问题中附上密码、私密草稿、Key 或完整备份。
