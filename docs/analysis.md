# 讨论分析使用说明

此功能随 0.4.3 GitHub 预发布版提供，仍处于试用阶段；真实模型准入及已安装扩展的完整流程尚未验收。验证进度见 [验收记录](analysis-validation.md)。

## 从一篇帖子开始

1. 在过早客主题页点击「讨论分析」，扩展会采集本帖文字并自动调用默认模型，随后展示分析结果。日常界面只保留结果、主张与证据、回复观察。
2. 尚未配置模型时，填写自己的 HTTPS API 地址、模型 ID 和 API Key。只有一个配置时自动成为默认；多个配置可点击「设为默认」。从分析入口进入设置，保存可用配置后会继续本帖分析。
3. 不满意时，在结果页选择另一个模型并点击「重新分析」。旧结果保存在历史中；这次选择不会修改默认模型。失败时可以点击「重试」，继续未完成部分。

模型设置会说明发送范围和费用。点击分析会将本帖文字、链接、主张及核查材料发送到所选 API 服务，费用由服务商收取；不会发送编辑器草稿或原站 Cookie。浏览器重启、扩展重载后，会话 Key 需重新填写。

已有完成报告时直接展示，打开或刷新不会反复产生模型请求。执行中再次点击论坛入口只唤起现有侧栏；同一帖的新任务及同一报告分别通过 Web Locks 防止多个窗口重复执行。网页合成点击不会启动分析。仅访问帖子不会调用模型。

「更多 → 高级工作区」保留采集检查、调用预算、补充资料、历史导出、固定输入复跑和模型校准。默认分析仍受 30 次调用及原件读取额度约束，失败重试保留已用额度；超限会停止并明确提示。简单模式对尚未授权的来源保留待核，继续整理其他可用内容，不会绕过来源权限，也不会把模型记忆伪装成已读证据。

主张上的「核对主张摘录」显示原文和字符定位，包括尚未进入核查问题的主张。高级工作区的「指出摘录错误」可选择发言及原因，重新采集并建立带复核标记的新版本；旧报告保留，新的主张和评价从空白开始，仍需再次主动开始分析。重新采集不等于已经证明错误修复。

## 什么算证据

检索结果只作为线索。只有实际读取到的公开网页、文字 PDF 或用户补充材料，才进入可核对的来源记录。读取失败、登录限制、扫描 PDF、缺页和语境不全都会保留缺口。

HTML 表格保留行、单元格和合并标记，空单元格不会补成 0；表头与数值的含义仍须核对。PDF 仅提取文字层，多栏、表格和上下标可能出现阅读顺序差异，数值及单位须对照原页确认。读取到文字本身不代表这些内容已成为核验通过的事实。

「已读取」表示取得了文本，不代表来源可信或主张为真。支持、部分支持、冲突、不可比和待核分开展示。来源的发布者、日期、定位、摘录、提供者及限制可展开检查；同源材料的数量不能当作多份独立佐证。

数据表保留原值与原始单位；缺值保持未知。明确的单位尺度换算由固定程序执行，导出包含原值、公式和规则版本。不自动换汇、跨期推算或外推人群；换成相同单位仍不代表统计口径可比。

来源容量或检索预算耗尽会停止后续请求，记录本次未继续执行的问题与检索方向，保留已经取得的材料；这些缺口不表示没有证据。

每个核查问题在实际形成时冻结目标口径、资料类型、正向和反向问题、10 分钟截止期限及最多 2 次检索。目标口径逐项沿用主张；原文没有说明的范围不由程序补全。失败尝试计入次数，恢复不会重置期限或次数。参考材料的 `plan: null` 表示没有可执行计划，不伪造历史检索。

自动取证默认有 24 MiB 原件累计读取额度及最多「来源上限 × 3」次读取尝试，每个文件最多 8 MiB。请求前保留额度，成功后按实际正文大小结算；失败、中断保守保留预留额度，重启恢复不重置。预算记录损坏或丢失会停止读取，自动任务不存在时不会降级为手工请求。该额度限制正文读取，不是底层网络流量或费用承诺。下方手动 URL/文件补充是独立的主动读取，受单文件及材料份数限制，不计入本轮自动取证额度。

高级工作区可选配置 Tavily 检索 Key。没有检索 Key 时，可读取帖内来源链接，或自行补充公开 URL、TXT、HTML、文字 PDF。访问新的来源域名需要单独授权。

## 如何理解回复观察

每个评价单元分别记录回应覆盖（R）、举证关系（E）、推导连接（L）、范围边界（B）。维度等级 0、1、2 不合成总分；不适用（NA）、适用性待确定（P）、无法判断（U）不是低分。

主张真假、作者原先是否举证、系统后来补了什么材料是不同问题。情绪表达可以与有效论证同时存在。页面只汇总本帖中观察到的回复、材料与纠正事件，不给参与者做人格判断、跨帖画像或排行榜。

## 开放模型与固定校准

高级工作区的「模型校准」按固定样例、固定配置和固定重复次数执行整轮记录。接口、型号、声明版本、参数、规则和样例指纹都会参与配置匹配；失败、取消、中断和可能已发送的请求保留预算占用，不能只挑答对结果计算成绩。

当前内置 21 个合成样例，每个重复 3 次，共 63 个执行单元；抽取单元可能需要多步调用。默认 30 次预算仅适合小额试跑，不能完成整轮校准。

新采集任务在开始时核对本机资格：仅精确配置通过当前试验条件时显示「标准分析试用」。开始、恢复及每次模型请求都检查版本与参数；服务返回型号变化后停止，并要求漂移之后新建整轮校准，旧回执重新算分不能恢复资格。流程版本变化后，旧批次保留在本机，不参与当前准入。报告另列结构校验、采集范围和材料状态；配置合格不代表每条结论已经核验。

当前内置材料为合成试验集。连接可用、JSON 合格、结构字段一致、参考评级一致与真实语义正确是不同结果。试验条件通过不等于独立专家认证，也不能保证不同服务商对所有新帖子结论一致。正式开放标准分析仍需真实配置、留出材料和新帖验证。

「复跑与对比」始终为探索记录，不自动升级标准模式。它提供两个轨道：固定整份原文重做主张抽取；固定原文、主张、问题与证据重做回复评价。输入不同时禁止冒充同输入一致率；模型间多数票不会自动变成真值。

## 命令行校准

仓库提供 `node scripts/analysis-calibrate.mjs --help`。准备仅含配置与 Key 环境变量名称的 JSON 后，先预览：

```sh
node scripts/analysis-calibrate.mjs --config /path/to/models.json --max-calls 100
```

默认预览不读取 Key、不联网、不写文件。只有显式加入 `--execute` 才读取配置指定的 `GZK_ANALYSIS_KEY_*` 环境变量，并按顺序执行；不要把 Key 写进 JSON、命令参数或聊天。`--max-calls` 是整个命令所有配置共用的 1–500 次上限，不是每个模型各自的额度。

首次调用前保存全部配置的完整样例矩阵，失败、取消和预算不足的槽位保留。结果写入 `artifacts/analysis-calibration/<唯一运行目录>/`，文件权限 0600；重复执行建立新批次，不自动重试或恢复。CLI 报告与检查点不能导入成为扩展的受信资格。当前只验证了模拟 HTTP、默认预览与命令入口，尚无真实模型校准结果。

## 取消、历史和导出

简单模式显示「正在分析」与停止按钮，完成后展示结论。高级工作区各页顶部的「本轮分析进度」持续显示已保存步骤、主张、可读材料、评价单元及调用占用；切换到模型设置等页面后仍可取消分析。结果按检查点更新，尚未完成时保持「部分完成」。你正在展开或聚焦原文时，任务和复跑队列会继续执行，但不会替换正在阅读的内容；点击「查看已保存结果」可主动刷新。导出对应当前显示的报告版本。

已完成步骤保存在本机，取消后不会继续安排下一次请求。删除分析会保留仅含记录 ID 的删除标记，阻止另一窗口晚到的检查点复活旧任务；再次分析需要建立新版本。服务商已经收到的请求可能仍然计费。重新打开历史可以继续未完成步骤；成功步骤的指纹须通过检查，不会静默改写原始输入。

分析包 JSON 包含原文、主张、来源正文、评价、版本、指纹和可复算的单位换算；不包含 Key。分享前应检查其中的帖子内容和补充材料是否适合公开。导入会检查结构、引用与完整性，导入记录不会自动取得本机校准资格。

Key 仅保存在扩展受信上下文的会话存储，浏览器重启或扩展重载后重新填写；不进入网页脚本、同步存储、报告和导出包。完整边界见 [隐私说明](privacy.md)。
